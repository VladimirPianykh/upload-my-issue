# Фильтрация issue по зависимостям

Фильтрация issue позволяет находить все задачи, которые необходимо выполнить до заданной задачи, все задачи, которые следуют за заданной задачей, все задачи, связанные с заданной задачей через связь «relates to» (цепочки любой длины), или все задачи, связанные с ней любой из трёх связей. Фильтр не изменяет зависимости между issue и работает совместно с остальными фильтрами.

## 1. Поведение фильтра

- Фильтр поддерживает четыре режима: `Зависимые`, `Зависимости`, `Relates to` и `Любая связь`.
- Режим `Зависимые` пропускает только issue, которые прямо или транзитивно зависят от выбранного issue.
- Режим `Зависимости` пропускает только issue, от которых прямо или транзитивно зависит выбранный issue.
- Режим `Relates to` пропускает только issue, которые прямо или транзитивно связаны с выбранным issue связью «relates to» GitHub. Эта связь симметрична, поэтому её «циклы» допустимы и ошибкой не считаются.
- Режим `Любая связь` пропускает issue, удовлетворяющие хотя бы одному из условий режимов `Зависимые`, `Зависимости` и `Relates to`.
- Сам выбранный issue не попадает в результаты фильтра.
- Каждое issue проходит фильтр не более одного раза независимо от количества путей зависимости, по которым оно связано с выбранным issue.
- Транзитивный обход учитывает цепочки зависимостей любой длины.
- При обходе зависимостей учитываются все промежуточные issue независимо от того, проходят ли они остальные фильтры.
- Несколько фильтров зависимостей работают одновременно по принципу пересечения результатов: issue отображается, только если проходит каждый из них.
- Фильтр зависимостей работает совместно с остальными фильтрами по общим правилам их применения.
- При отсутствии результатов отображается состояние пустого списка, предусмотренное существующим механизмом.

## 2. Ввод фильтра через поисковую строку

- Пользователь начинает ввод фильтра зависимостей с конструкции `!dep#`, `!idep#`, `!rel#` или `!con#`.
- Конструкция `!dep#` соответствует режиму `Зависимости`.
- Конструкция `!idep#` соответствует режиму `Зависимые`.
- Конструкция `!rel#` соответствует режиму `Relates to`.
- Конструкция `!con#` соответствует режиму `Любая связь`.
- При вводе символа `!` появляется автодополнение доступных конструкций.
- Механизм автодополнения конструкций допускает расширение при добавлении новых вариантов.
- После ввода конструкции пользователь вводит название issue для поиска подходящей карточки.
- Список карточек отображается, когда каретка находится после `#` или внутри следующего за ним слова до первого пробельного символа включительно по позиции каретки, но не после этого слова.
- Автодополнение определяется конструкцией слева от каретки и её текущим положением.
- При перемещении каретки в позицию, для которой автодополнение не предусмотрено, список закрывается либо заменяется соответствующим текущей позиции автодополнением.
- При продолжении ввода в поисковой строке автодополнение появляется снова, если текущая позиция соответствует условиям его отображения.
- При вставке конструкции через буфер обмена действуют те же правила отображения автодополнения, что и при ручном вводе.
- Если в поисковой строке присутствует несколько конструкций фильтрации, список карточек отображается только для конструкции, соответствующей текущей позиции каретки.
- До выбора карточки конструкция фильтрации остаётся частью обычного поискового запроса.
- Если по введённому тексту не найдено ни одного issue, список остаётся открытым и отображает сообщение `Issues не найдены`.
- Закрытие списка поддерживается клавишей `Escape`, кликом вне списка и потерей фокуса.
- При возврате фокуса в поисковую строку автодополнение определяется заново по текущему положению каретки.

## 3. Выбор issue

- При выборе карточки создаётся отдельный фильтр зависимостей на панели фильтрации.
- После выбора карточки соответствующая конструкция вместе с введённым для неё текстом удаляется из поисковой строки.
- Остальной текст поисковой строки сохраняется без изменений.
- Выбранный фильтр отображается на панели фильтрации в неизменяемом виде.
- Для изменения выбранного issue или режима пользователь удаляет существующий фильтр и создаёт новый.
- Удаление фильтра выполняется нажатием крестика на его блоке.
- При удалении фильтра его конструкция не возвращается в поисковую строку.
- Несколько фильтров зависимостей могут одновременно присутствовать на панели фильтрации.

## 4. Карточки автодополнения

- Список автодополнения содержит карточки issue, соответствующих введённому тексту названия.
- Каждая карточка отображает название issue, статус, количество зависимостей и количество зависимых issue.
- Список поддерживает перемещение между карточками стрелками вверх и вниз.
- Нажатие `Enter` выбирает текущую карточку.
- Нажатие `Tab` выполняет то же действие, что и `Enter`, если карточка выбрана в списке.
- Нажатие `Escape` закрывает список без выбора карточки.
- Стандартные способы закрытия списка не создают фильтр без выбора карточки.

## 5. Обработка зависимостей и ошибок

- Вычисление зависимостей обнаруживает циклы в обходящемся графе направленных связей (зависимости и зависимые) с помощью `assert`; для симметричной связи «relates to» проверка циклов не выполняется.
- При обнаружении цикла вычисление списка прерывается, и пользователю отображается сообщение об ошибке по существующему механизму обработки ошибок списка, аналогичному ошибке `bad credentials`.
- При любом исключении во время вычисления списка дальнейшее вычисление списка прерывается, а ошибка отображается через тот же механизм.
- Ошибка вычисления не приводит к тотальному падению приложения.
- Отсутствие результатов фильтрации не считается исключением и обрабатывается существующим механизмом отображения пустого списка.
